# 碎碎念时刻

## AI时代下的嵌入式软件的困惑和思考？

今年从年初体验了GPT-5、Deepseek和Qwen后，特别是再agent下辅助开发后，也对AI对于程序员的影响和冲击有了更多的思考。

以我体验看来，AI对于实现局部化的最优代码已经完全取代了大部分程序员。这不是危言耸听，AI可以接触大量的优质代码进行训练，相较于大部分程序员，都有更广阔的视野，从而能够实现更优秀的代码实现。在目前的时代，AI就是最好的学习编程的老师，不是单一行业，而是涉及编程相关各行各业；无论你是消费电子、金融、医疗、游戏相关，都逃不脱这个泥潭。

### AI对于测试工具的影响

对于AI需求，如实现文件读取，计算CRC、MD5、HASH或者SHA；制定协议和下位机通讯交互，或者写个工具进行文件格式转换，如bmp转jpg、png，提取原始数据；这些以前可能需要去理解各种算法和接口，才能实现的应用，现在AI已经可以无缝实现需求，可以开箱即用。对于涉及UI界面和具体功能需求的方案，只要列出完整的框架和需求，配合Agent工具，也可以方便的生成。

AI是快速提高了效率，可是我有时在想，积累了十几年的经验被一种更高维度的技巧碾压了，空闲下来，其实充满了空虚感和恐惧心。我虽然是从事单片机开发的，也系统的学习过嵌入式Linux；在实践中，为了方便测试，我自学过Python、C#、网页前端，用于开发上位机，时候也觉得自己技术不错。可是这一丁点的自满，在AI只花了三分钟就生成了可以使用的测试上位机后荡然无存。其实这是很痛苦的经历，人生有几个十年，过去的经验被ai无情的碾过去了。如果我现在踏入嵌入式行业，一定不会花费大量时间只是去学习这些上位机语言语法，它们都只是应用的一部分。从框架的角度，这些测试工具，其实最适合用AI来开发，**明白需求是什么，注意点是什么**，让AI直接生成，比自己去学习在开发方便也快捷的多。这并不是AI时代不需要学习语言，而是从理解语言的语法细节，变成理解语言概念后，将需求转换成容易处理的文件语言，让AI来处理，生成代码。

### AI对嵌入式开发的影响

上面是非本职的上位机工具的影响，对于单片机和嵌入式的影响，AI的影响同样是天翻地覆。可以说，AI已经取代了驱动行业中大部分相对简单的工作，这里说的简单，就是除了USB、TCP/IP、电机控制、UI框架这类复杂且和需求实时相关的项目，对于常用的SPI、I2C、UART、CAN、SDIO，以及建立在这些接口上的外设驱动如ap3216、max17261等，AI掌握的信息更全，给出的经验也更准确，高于目前驱动工程师的平均水平。

对于传统的驱动开发项目，主要从两个方向进行完整的开发。

1. 正向的开发实现，根据硬件、结合手册和开发经验，进行软件编写的实现，确定流程和参数的配置。这一方面AI已经处理的比较完美，就像上面说的，AI取代了驱动行业大部分工作。
2. 反向的调试应用，下载代码直接运行，根据打印信息，实际的输出、示波器的显示，确定软件开发问题，修复后重新测试，最终确保流程工作正常符合预期。

对于目前AI Agent的应用，对于反向调试方面，还需要开发者根据实际情况结合AI分析可能问题，并反馈告知，然后重新进行正向的开发实现，这是整个流程中堵塞的地方。例如无法访问外部的器件，可能是软件配置问题、逻辑处理问题；或者单纯的硬件问题，如引脚损坏、电源异常、芯片损坏；当AI实现代码直接正常工作时，开发者会觉得很轻松，也很无用；反而不能工作时，如何查找分析问题，提供给AI有效信息，排除问题，才是项目继续运行下去的关键。这样看来，AI时代，嵌入式驱动开发者存在的价值正是于此，在AI没有机械手辅助去获取外部世界信息的情况下，人充当了这个桥梁，这也是需要深度钻研的地方，在机器人完全取代之前，还有一定的岗位保留下来。

对于应用来说，嵌入式应用和桌面端除了性能要求差别、会访问硬件来说，并没有本质的区别，当然也是被取代的重灾区。如何从软件开发者，转换为架构开发师可能是唯一出路。对于嵌入式来说，其实现从需求出发，分解为软件、硬件、结构需求，对于软件又根据使用场景和应用可以模块化处理，这方面AI可以辅助处理，但是框架是需要人来把控，构建合适框架，再由AI来填充，然后在调试验证阶段，由配合AI分析结果；可以说，不会使用AI，效率远远赶不上，可能真的要被淘汰；而不会很好使用AI，也会慢慢边缘化；这个时代，真是对于知识的最大平权，而作为出卖知识劳力换取工资的技术者，则真的有些兴奋和恐惧。

### 未来该怎么办

没有人可以预测未来，但是可以提高当下；可以去学习语言，但是不要去追逐细节，不要被语法细节困住。

1. 在AI时代，快速理解代码的能力是重要的，AI可以快速生成几千几万行代码，但是当语言交流处理流程卡住后，就需要人为去疏通，能够理解语言就天然具有更高的效率，如果完全不懂技术，只能烧大量的token来试错抽奖。
2. 把经验而不是技术作为知识，技术是廉价的，但是经验还是有价值的，知道想要什么、需求什么、会有什么可能的坑，就可以更好的设计方案，让AI更方便的进行开发。

AI时代更应该学会总结，从整体方面思考，并学习如何将AI纳入自己的工作流，在这个阶段保持不掉队吧；未来什么样，谁又能说清楚呢?
